# {{< icon "fa fa-server" >}} KamPlexFS

This is a backend for the JSON REST API of a KamPlexFS server.

KamPlexFS also has an S3 interface which rclone can use with the
[s3 backend and `provider = KamPlexFS`](/s3/#kamplexfs). Both backends
see the same objects with the same names.

Paths are specified as `remote:bucket` (or `remote:` for the `lsd`
command). You may put subdirectories in too, e.g.
`remote:bucket/path/to/dir`.

This makes a config like this:

```ini

```

List the buckets

```console
rclone lsd kamplexfs:
```

Copy a local directory into a bucket

```console
rclone copy /home/source kamplexfs:bucket/backup
```

### Authentication

The server authorizes each request with a JWT signed with its
`jwt_secret`. Give rclone the same secret with `jwt_secret` and it
signs its own tokens, each valid for `jwt_ttl` (default 1 hour) and
renewed before they expire. `jwt_ttl` must not be longer than the
server's `jwt_max_ttl_seconds`, which defaults to 24 hours.

The tokens can be restricted with the `allowed_prefixes` and
`allowed_methods` options, which set the claims of the same names.

If you would rather not give rclone the secret, set `token` to a token
made elsewhere instead. rclone can't renew it, so requests fail once it
expires.

The token is sent in the `Authorization` header, never in the URL.

### Buckets

rclone makes a bucket when a directory, file or server-side copy
needs it, and removes it with `rmdir` or `purge` once it is empty.
The bucket endpoints are mounted next to the file ones, at
`/api/v1/buckets` for the default `route`.

Older servers without the bucket endpoints can't make or remove
buckets, so there the buckets must be made on the server first and
are left in place when emptied.

A token which isn't allowed to make buckets can still use the ones
which exist.

### Modification times and hashes

The modification time is stored with each file. It has a precision of
1 second. Servers which store sub-second modification times are
detected from their listings and are then sent the full modification
time on upload.

Servers which can set the modification time of an existing file do so
in place. Older servers can't, so rclone uploads the file again when
only its modification time has changed.

MD5 hashes are supported. A file which the server hasn't hashed yet
has no hash.

### Empty directories

A server in direct-fs mode stores empty directories. A server in
packed-volume mode can't, so rclone detects this the first time it
makes a directory and then treats directories as existing only while
they hold files.

### Server-side operations

Copy, move and directory move are done on the server. Moving a
directory is a single request whatever it holds.

### --fast-list

This backend supports `--fast-list` which lists everything below a
directory in one paged scan.

Older servers leave empty directories out of those listings, which a
server in direct-fs mode can have. With those it is only used in
packed-volume mode, and otherwise each directory is listed in turn.

### Restricted filename characters

The same characters are encoded as in the [s3 backend](/s3/#restricted-filename-characters),
so an object has the same name through both backends.

### Standard options

Here are the Standard options specific to kamplexfs (KamPlexFS).

#### --kamplexfs-url

URL of the KamPlexFS server.

E.g. "http://localhost:8080".

Properties:

- Config:      url
- Env Var:     RCLONE_KAMPLEXFS_URL
- Type:        string
- Required:    true

#### --kamplexfs-jwt-secret

The server's JWT secret.

This is the jwt_secret from the [security] section of the server's
config. It is used to sign short lived tokens for each request.

Leave blank to use a fixed token instead.

**NB** Input to this must be obscured - see [rclone obscure](/commands/rclone_obscure/).

Properties:

- Config:      jwt_secret
- Env Var:     RCLONE_KAMPLEXFS_JWT_SECRET
- Type:        string
- Required:    false

### Advanced options

Here are the Advanced options specific to kamplexfs (KamPlexFS).

#### --kamplexfs-token

A fixed JWT to use instead of the JWT secret.

rclone can't renew this token, so once it expires requests fail.

Properties:

- Config:      token
- Env Var:     RCLONE_KAMPLEXFS_TOKEN
- Type:        string
- Required:    false

#### --kamplexfs-jwt-ttl

Lifetime of the tokens signed with the JWT secret.

This must not be longer than the server's jwt_max_ttl_seconds, which
defaults to 24h.

Properties:

- Config:      jwt_ttl
- Env Var:     RCLONE_KAMPLEXFS_JWT_TTL
- Type:        Duration
- Default:     1h0m0s

#### --kamplexfs-allowed-prefixes

Path prefixes to restrict the signed tokens to.

A comma separated list which is put in the allowed_prefixes claim of
the tokens. Leave blank for no restriction.

Properties:

- Config:      allowed_prefixes
- Env Var:     RCLONE_KAMPLEXFS_ALLOWED_PREFIXES
- Type:        CommaSepList
- Default:     

#### --kamplexfs-allowed-methods

HTTP methods to restrict the signed tokens to.

A comma separated list which is put in the allowed_methods claim of
the tokens. Leave blank for no restriction.

Properties:

- Config:      allowed_methods
- Env Var:     RCLONE_KAMPLEXFS_ALLOWED_METHODS
- Type:        CommaSepList
- Default:     

#### --kamplexfs-route

The route the JSON API is mounted on.

The bucket endpoints are expected next to it, e.g. /api/v1/buckets
for /api/v1/files.

Properties:

- Config:      route
- Env Var:     RCLONE_KAMPLEXFS_ROUTE
- Type:        string
- Default:     "/api/v1/files"

#### --kamplexfs-list-chunk

Size of listing chunk.

The server may return fewer.

Properties:

- Config:      list_chunk
- Env Var:     RCLONE_KAMPLEXFS_LIST_CHUNK
- Type:        int
- Default:     1000

#### --kamplexfs-encoding

The encoding for the backend.

See the [encoding section in the overview](/overview/#encoding) for more info.

Properties:

- Config:      encoding
- Env Var:     RCLONE_KAMPLEXFS_ENCODING
- Type:        Encoding
- Default:     Slash,InvalidUtf8,Dot

#### --kamplexfs-description

Description of the remote.

Properties:

- Config:      description
- Env Var:     RCLONE_KAMPLEXFS_DESCRIPTION
- Type:        string
- Required:    false

## Limitations

User metadata isn't supported.

Resumable (TUS) uploads aren't used yet, so a failed upload restarts
from the beginning.
